# AgentForge · 工程流水线控制台

把「需求 → 规划 → 架构 → 编码 → 门禁 → 产物」做成一个可以跑的控制台。

**单文件 · 零依赖 · 无后端 · 不调用任何模型**

## 它不是静态截图，输入变了结果就变

页面上有两个真实在跑的引擎：

### 1. 本地规则引擎（生成）

左侧的任务描述会被解析成三样东西：

- **领域**：订单导出 / 用户权限 / 商品检索 / 支付回调 / 消息推送 / 页面交互
- **约束**：时间范围 / 数据量 / 并发 / 权限 / 异常 / 分页 / 校验
- **形态**：后端接口 还是 前端页面

生成的产物完全由这些决定。举个实际对比：

| 输入 | 接口 | 门禁分数 | 差异 |
|---|---|---|---|
| 订单导出（含时间/万行/分页） | `/api/orders/export` | 20 → 85 | +18 / -5 |
| 支付回调（含签名/重试） | `/api/payments/callback` | 20 → 75 | +12 / -5 |
| 商品搜索页 | 走前端模板 | — | — |

**换个任务，接口名、代码、边界说明、扣分项都不一样。**

### 2. 质量门禁（评分）

对**生成的文本**做五条规则校验，从 100 分往下扣：

| 规则 | 扣分 |
|---|---|
| 代码块是否闭合 | -25 |
| 章节是否完整（≥3 节） | -20 |
| 中英文比例（≥25%） | -15 |
| 长度是否充足 | -10 |
| 是否说明边界情况 | -10 |

低于阈值触发重试；重试产出补全是真实发生的，所以**差异面板里的每一行都来自两次生成的实际对比**。

## 流水线

| 阶段 | 输出 |
|---|---|
| **Planner** | 识别约束、拆交付项 |
| **Architect** | 定接口、选分页策略 |
| **Coding** | 生成实现 |
| **Debug** | 门禁校验 + 判定 + 修复 |
| **Deploy** | 打包产物 |

每个阶段都展示 **观察 / 权衡 / 结论**，可点击展开收起。

---

## 试着改这几处

- **改任务描述** → 领域、接口、产物、分数全变
- **阈值拖到 90** → 第二轮 85 也过不了，会继续重试
- **拖到 40** → 一次通过

## 说明

产物与评分由**本地规则引擎**计算，不调用任何模型，也没有任何网络请求。
这样做是因为：**演示必须永远能跑通**——不依赖 Key、不依赖额度、不会白屏。
